# 2026-11-02: Builds and Releases

## 1. Two Workflows: build.yml and release.yml

### 1.1 Header & Context
- **Date:** 2026-11-02.
- **Task:** the engine's builds and releases on GitHub Actions, in its public repository.

### 1.2 User Request
> In motorust-engine there should be two workflows: `build.yml`, which runs the tests and makes the builds; `release.yml`, run by hand, the version an input (major, minor, patch), which runs `build.yml` and then makes a GitHub release with the builds attached. The repository is, and will stay, public.

### 1.3 Implementation Details
- **Something to build**: the engine is a library, so its builds are its demo, `src/main.rs` (new, the `motorust-engine` executable): the engine's app on its own content (the demo circuit and roster), the crash report installed, macOS's latency settings (`latency::begin`), no console window on Windows in release. `cargo run --release` runs it.
- **The crash report in the engine** (`src/crash.rs`, new): the panic hook the game had in its `main.rs` (`<folder>-crash.log` beside the executable; on Windows, in its folder in `%APPDATA%` too, with a message box), now `crash::install()`, used by the demo and the game alike; its message is `crash::report` (tested: `the_report_names_the_game_its_build_and_its_file`), with the build from `crate::build()`.
- **`.github/workflows/build.yml`** (replacing `ci.yml`): on push to `main`, on pull requests, by hand, and called by `release.yml` with a `version`.
  - `test`: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
  - `build`, after it, a matrix on GitHub's runners: Linux x86_64 (`ubuntu-latest`), Windows x86_64 (`windows-latest`), macOS Apple Silicon and Intel (`macos-latest`, the Intel one cross-built). With a version, `Cargo.toml` takes it before building, so the executable carries it; without one, the label is `dev-<sha>`. Each packed as `motorust-engine-<label>-<target>` (`.zip` on Windows, `.tar.gz` elsewhere) with the executable, `README.md`, the licences and `assets/CREDITS.md`, uploaded as an artifact.
  - `wasm`, after `test`: `wasm-bindgen-cli` at `Cargo.lock`'s version, `web/build.sh`, packed as `motorust-engine-<label>-wasm32-unknown-unknown.zip`.
  - Only GitHub's runners, no self-hosted ones as the game's workflow can use: the repository is public, and a pull request from a fork must never run on a machine of ours.
- **`.github/workflows/release.yml`**: by hand, `bump` one of `patch`, `minor`, `major`.
  - `version`: from the higher of the last `vX.Y.Z` tag and `Cargo.toml`'s version (0.0.17 now: patch gives 0.0.18, minor 0.1.0, major 1.0.0); fails if the tag exists.
  - `build`: `build.yml` with that version.
  - `release`: the artifacts downloaded, `SHA256SUMS.txt` made, `Cargo.toml` and `Cargo.lock` given the version and committed to `main` (`vX.Y.Z [skip ci]`, as it was just built), and `gh release create vX.Y.Z` on that commit with every build and the sums, its notes generated.
- **The web version** (`web/`, new): `web/build.sh` builds the demo for `wasm32-unknown-unknown` and runs `wasm-bindgen` on it (out as `motorust_engine.js` and `motorust_engine_bg.wasm`, the target folder asked of `cargo metadata`, so it works in a game's workspace too); `web/index.html`, a page of its own (the canvas `#motorust-engine`, named after `game.ron`'s folder; a Start button, so the browser lets it play sound; the download's progress; the engine marking it ready with `data-motorust="ready"`).
- `README.md`: running the demo, `web/build.sh` among the tools, the builds and releases. `.gitignore`: `/dist`.

### 1.4 Verification & Testing
- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` (and in release), `cargo test` in the game's workspace, the engine with its new test; the workflows parsed as YAML; the version's arithmetic run on a few cases (0.0.17 with no tag: 0.0.18, 0.1.0; with v0.1.3: patch 0.1.4) and the substitutions in `Cargo.toml` and `Cargo.lock` tried on copies.
- Not run here: the builds for Windows, macOS and the web, nor the release itself; they run on GitHub's runners, the first with the push of this commit.
