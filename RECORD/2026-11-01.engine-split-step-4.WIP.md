# Step 4 of the Engine's Split: the Workspace (2026-11-01)

Step 4 of "The engine apart from the game" (`ROADMAP.md`): the engine in a crate of its own, `motorust-engine/`, and the game depending on it. How it is cut, decided by the user, is in `RECORD/2026-10-31.engine-split-plan.WIP.md`, section 10: the seams first, in this crate (4a what the code names becomes data, 4b the themes as plugins, 4c the engine's tests on its own content, 4d two packs), then the move (4e).

## 1. 4a: What the Code Named, as Data

### 1.1 User Request
> "Vale a todo, empieza por 4a" (yes to everything, start with 4a): the proposal accepted as it was (Bahía GP the engine's demo circuit, without a song; the generic features staying in the engine; the circuits' themes as a map; the Meshy bikes' measures as data; the engine's API broad first), and 4a first.

### 1.2 Implementation Details
- **The Meshy bikes' measures as data**:
  - each model's folder has a `model.ron` (new, eight): its `geometry` (axles, wheel radii, steering head, grips, pegs, seat), `steers` (whether its fork and bars turn; `true` if left out) and `tyres` (`Soft`, `Medium` or `Hard`; `Medium` if left out), written from the old statics in `imported.rs` and the compounds `tyre::Compound::of` named by design;
  - `imported::Model` derives `Deserialize` (`Geometry` and `Compound` too); `imported::model(folder)` reads it the first time it is named and keeps it (leaked, in a list behind a mutex: two names of a folder are the same model, `PartialEq` by address), refusing a name that is not a folder; `imported::models()` lists those named so far, each with its `index`. The eight statics and the `model!` macro are gone;
  - `Design` is `Afilada`, `Escudo`, `Alerones`, `Rombo` or `Model(&'static Model)`; a file writes `Model("shogun")` (`DesignFile`, `try_from`). `Design::ALL` is gone: `Design::BUILT_IN_CODE` (the four) and `Design::all()` (those, then the models named so far, by `index`), which `BikeBlueprint` builds its bodies from, the roster read first (`init_resource::<Roster>`), so every model it names has its body. `Compound::of` asks the model; `details`, `build` and `plates` match `Design::Model(_)`;
  - `assets/bikes/roster.ron` names each bike's model by its folder; `assets/pack.txt` lists each folder's `model.ron`;
  - the tests that went through the eight statics go through the roster's models (`designs::every()`, which reads the roster first);
  - `tools/import_models.py` writes `model.ron` (keeping its `tyres` if it was there) instead of printing a block to paste into `imported.rs`.
- **The music not a track's, as data**:
  - `assets/music/music.ron` (new): the menus' song (`menu`, optional) and the chill songs (`chill`), each with its `name` and its `song` (file, length, loudness), read into the `Songs` resource (`src/sound/music.rs`), inserted by the `SoundPlugin`. `CHILL` and `MENU` are gone;
  - a circuit's `song` is optional (`Option<Song>`, `data::some_song`; left out, none): the engine's demo circuit will have none. `Song` derives `Deserialize` through `data::SongFile` (`try_from`) and is `Copy`;
  - `Tune::song` gives a song only where there is one; `play_music` starts none where there is none (the menus with no song, a track with none); the `Music` component keeps its song (its gain and length);
  - free ride's music: `MusicMode::tunes` lists only the tunes with a song, `FreeMusic::tune` is `None` where there are none, and `next_mode` goes on to the next of what plays that has songs to play on this track (the chill songs left out if there are none; the track's if it has none), the track's if none has.
- **The game's identity, as data**:
  - `assets/game.ron` (new): its `title` (the window's, the crash report's), its `folder` (where its settings and logs are kept, its crash report's name, the web page's canvas), its `logo` (`plain: "MOTO"`, `accent: "RUST"`) and its `icon` (optional);
  - `src/game_info.rs` (new): `GameInfo`, read the first time it is asked for (`info()`, in `main` before the settings are read), and `read_already()` for the crash report, which reads no file as the game falls (and says "The game" if it had not been read);
  - used for the window's title and canvas, the settings' and the logs' folders, the performance log's and the benchmark's headings, the crash report, the window's icon, the start menu's logo and the menu's width. Not a resource the game inserts, as the proposal had it, but a file of its pack: the engine needs it before the app is built (the settings' folder), and the game then names itself with no code.
  - Left as they are: the `MOTORUST_*` environment variables of the development tools (the benchmark, the start from a point of the lap), the web page's `data-motorust` (the game's own page), the Windows and macOS icons and `Info.plist` (packaging, the game's).
- **Docs:** `docs/models.md` (the table, the roster, the tyres, the importer, adding a bike), `docs/architecture.md` (`designs.rs`, `imported.rs`, `src/game_info.rs`, `music.rs`, `assets/`), `docs/tracks.md` (a song optional), `ROADMAP.md`.
- `RECORD/2026-10-31.content-pack.WIP.md` renamed `.completed.md`: step 3 is done as far as the split needs (its last section says what is left, for the editor).
