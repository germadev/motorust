# Installer for Linux and macOS (setup.sh) and quick install on the web

- **Date:** 2026-10-22
- **Task:** Publish an installer script at <https://motorust.germade.dev/setup.sh> that installs the game on Linux and macOS, links it into `$PATH` and offers install, update and uninstall. Add a snippet to the web page that downloads and runs it with `curl` or `wget`, and remove the GitHub link from the page.
- **Status:** Completed

## 1. User Request

The user asked for a script deployed at <https://motorust.germade.dev/setup.sh> that:

- Installs Motorust for Linux and macOS.
- Puts the executable in `~/motorust/motorust`.
- Creates a symlink in `~/.local/bin`, or in another directory of `$PATH` that the script detects.
- Checks whether the game is already installed when it runs, and then offers the options: install, update and uninstall (the third option of the original list was a duplicated "instalar"; the user confirmed it should be "Desinstalar").
- Tells the user how to start the game from the terminal (`motorust`) once it is installed.
- Is offered on the web page as a snippet that downloads the `.sh` with `curl` or `wget` and runs it.

The binary source was chosen by the user: the fixed version of the site (the version the web build publishes).

## 2. Implementation Details

### 2.1 The installer (`web/setup.sh`, new)

A single POSIX-ish bash script (bash 3.2 compatible, so it runs with the bash that macOS ships) that:

- **Detects the platform:** `uname -s` and `uname -m` give the Rust target triple (`x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`, `x86_64-apple-darwin`). Linux on ARM and any other system are refused with a clear message, since no build is published for them.
- **Knows the version:** the `__MOTORUST_VERSION__` placeholder is replaced by `web/build.sh` with the version of `Cargo.toml`, so the installer always downloads the release the site is publishing. If the file is run without that substitution (from the repository), it asks the site which version it publishes by reading `GAME_VERSION` from the page.
- **Downloads** `motorust-<version>-<target>.tar.gz` from `<site>/downloads/`, the same URL the download cards use: the Pages function (`functions/downloads/[file].js`) serves it from the R2 bucket and falls back to the GitHub release. `curl` and `wget` are both supported; `curl` shows a progress bar when the output is a terminal.
- **Checks the SHA-256** of the archive against `SHA256SUMS.txt` of the release, and only warns (without failing) when the sums cannot be fetched or the tools to compute them are missing.
- **Installs** the executable in `~/motorust/motorust` (atomic replace: copy to a temporary name, `chmod 755`, move) and writes the installed version in `~/motorust/.motorust-version`.
- **Links** it into `$PATH`: `~/.local/bin` when it is there, otherwise the first writable directory of `$PATH`, and `~/.local/bin` as a last resort. In that last case the script offers to add `export PATH="$HOME/.local/bin:$PATH"` to `~/.zshrc`, `~/.bashrc` or `~/.profile`. An existing file (not a symlink) at that path is kept as `.old`.
- **Offers the menu** the user asked for: *Instalar* (or *Actualizar* when the installed version is older, *Reinstalar* when it is the same), *Desinstalar* and *Salir*. The menu is always read from `/dev/tty`, never from the standard input, because the script usually arrives through a pipe (`curl | bash`) and reading the pipe would eat the rest of the script. Without a terminal it explains that and asks for `--install`, `--update` or `--uninstall`.
- **Uninstalls** the executable, the version file and the symlinks that point to this game (leaving other programs alone), and removes the folder if it ends up empty.
- Also takes `--install`, `--update`, `--uninstall`, `--dir PATH`, `--version` and `--help` for unattended runs, and reads `MOTORUST_SITE_URL`, `MOTORUST_RELEASES_URL` and `MOTORUST_HOME` from the environment.

### 2.2 The web build (`web/build.sh`)

Copies `web/setup.sh` to `dist/web/setup.sh` with the version filled in (`sed "s/__MOTORUST_VERSION__/$version/g"`) and the executable bit set, so the Cloudflare Pages deployment serves it at `/setup.sh`.

### 2.3 The web page (`web/index.html`)

- New **"Instalación rápida (Linux y macOS)"** block under the download cards, with the two commands and a button to copy each one (Clipboard API, with a "¡Copiado!" confirmation):
  - `curl -fsSL https://motorust.germade.dev/setup.sh | bash`
  - `wget -qO- https://motorust.germade.dev/setup.sh | bash`
- A note explaining that the game ends up in `~/motorust/motorust`, is linked into a directory of `$PATH`, runs with `motorust`, and that the script asks whether to install, update or uninstall.
- Styles for the block (`.quick-install`, `.cmd-row`, `.cmd`, `.cmd-copy`, `.cmd-note`) in the style of the rest of the page: dark glass panel, rust accent on the copy button, monospace command.
- **The GitHub link is gone:** the "Código fuente en GitHub" link and its now empty `.footer-links` wrapper (and the CSS rule) were removed from the page.

### 2.4 Documentation

## 3. Verification & Testing

- `bash -n web/setup.sh`: passes, also with the version substituted.
- The version substitution of `web/build.sh` was checked on its own: only the `version=` line is replaced, the result is valid bash and prints `0.0.10` with `--version`.
- **Fake site:** with a local HTTP server serving a fake `motorust-0.0.10-aarch64-apple-darwin.tar.gz`, the whole flow was checked with a fake `HOME`: install, symlink in `~/.local/bin`, version file, run of the executable, reinstall, uninstall (binary, version file, symlink and empty folder removed) and the "already up to date" message of `--update`.
- **Symlink in another directory:** with a `$PATH` without `~/.local/bin`, the link was created in the first writable directory of `$PATH`; with a `$PATH` where nothing is writable, the link went to `~/.local/bin` and the script printed the `export PATH=` line to add.
- **Menu:** driven through a pseudo terminal (`script`): *Salir*, *Desinstalar* and *Instalar* were checked, and the menu shows "Actualizar a la versión v0.0.10" when an older version is installed and "Reinstalar ... (ya estás al día)" when it is the same one.
- **`curl | bash`:** the script run through a pipe reads the menu from `/dev/tty` correctly, and the standard input of the pipe is never consumed.
- **Real download:** the script was run against the live site (`https://motorust.germade.dev/downloads/motorust-0.0.10-aarch64-apple-darwin.tar.gz`, 85 MB): the archive was downloaded, the SHA-256 matched `SHA256SUMS.txt` of the release, the binary was installed (`Mach-O 64-bit executable arm64`) and the symlink created.
- The three archives the installer needs (`x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`, `x86_64-apple-darwin`) answer 200 on the live site.
- The page was parsed with `html.parser` (no unclosed or crossed tags) and its module script checked with `node --check`.
- No Rust code was changed, so `cargo test`, `cargo fmt --check` and `cargo clippy` are not affected by this task.
