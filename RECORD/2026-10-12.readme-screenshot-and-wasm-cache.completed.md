### WasmFS?

- No, and it would not help: WasmFS is Emscripten's file system for programs built with Emscripten. Motorust is built for `wasm32-unknown-unknown` with `wasm-bindgen`, has no file system on the web and keeps its settings in `localStorage`. What avoids the download is caching the `.wasm` itself.

### Before this change

- `functions/motorust_bg.wasm.js` serves the `.wasm` from R2 with `Cache-Control: public, max-age=31536000, immutable`, but the page asked for it at a fixed URL (`./motorust_bg.wasm`). So:
  - Whether a reload reused it depended on the HTTP cache (an 84 MB file, about 33 MB compressed, may not be kept; a hard reload skips it).
  - Worse, after a release a browser that had kept it could pair the old `.wasm` with the new `motorust.js` (which is revalidated on every visit), and the game would fail to start until the browser dropped it.

### Versioned URL and Cache Storage (`web/build.sh`, `web/index.html`)

- `web/build.sh` computes the SHA-256 of `motorust_bg.wasm` (`sha256sum`, or `shasum -a 256` on macOS) and writes it into the page as `WASM_SHA256`, next to `WASM_BYTES`. It also adds the semicolon that the `WASM_BYTES` substitution used to drop.
- The page asks for `./motorust_bg.wasm?v=<first 16 hex digits>`: each build has its own URL, so the year-long `immutable` header is now safe. The Pages Function ignores the query string, so nothing changes on the server.
- After a download, the page keeps the `.wasm` in Cache Storage (cache `motorust-wasm`, keyed by the versioned URL) in the background while the player presses "Iniciar juego". Before keeping it, it checks the SHA-256 against `WASM_SHA256`: during a release R2 is updated before Pages, so for a moment the server can send a different build, which must not be kept. It then deletes the entries of older builds, so only one copy (84 MB) is kept.
- On the next visit, even after a hard reload, the page reads the `.wasm` from Cache Storage (checking its length against `WASM_BYTES`), shows "Listo, sin volver a descargarlo" and the start button at once.
- Any failure (no Cache Storage outside https and `localhost`, refused in a private window, quota, read errors) falls back to downloading, as before. The page in the repository, with no hash filled in, uses the plain URL and keeps nothing.

### Documentation (`docs/building.md`)

- `build.sh` steps mention `WASM_SHA256`. New "Caching the game" section: the versioned URL, Cache Storage, the fallbacks and why WasmFS does not apply.
- The release step now says how the web build is published: the `.wasm` is too large for Cloudflare Pages (25 MiB per file), so it goes to R2 and `functions/motorust_bg.wasm.js` serves it, and the rest goes to Pages after it.

## Verification & Testing

- **Web caching, end to end in headless Chromium (Playwright)**, with the real `web/build.sh` run against a fake `cargo` and `wasm-bindgen` (random 3 MB "builds" and a stub `motorust.js` that hashes what `init` receives), served by a local server that sends the same `immutable` header, with the HTTP cache turned off so only Cache Storage can avoid a download. All 16 checks passed:
  - `build.sh` fills in `WASM_SHA256` and `WASM_BYTES`.
  - First visit: one request, to `motorust_bg.wasm?v=<hash>`; "Descarga completada"; `init` gets build A; build A is kept.
  - Reload: no request; "Listo, sin volver a descargarlo"; `init` gets build A.
  - New build B: one request with the new hash; `init` gets B; only B is kept; the next reload downloads nothing.
  - Server sending another build than the page's: downloaded, warned about and not kept.
  - The unbuilt page from the repo: plain URL, nothing kept.
- **Cost for the real size (84 MB) in headless Chromium**, on this busy 4-core container: reading it back from Cache Storage 0.15 s; the one-time SHA-256 check 0.57 s and writing it 0.57 s, both in the background after the first download.
- **Rust:** no Rust changes (the screenshot harness was removed before committing). `cargo fmt --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `cargo test`: 200 passed.
- `bash -n web/build.sh` clean.
