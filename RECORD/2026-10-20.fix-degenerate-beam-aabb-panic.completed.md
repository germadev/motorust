# 2026-10-20 — Fix Degenerate Beam Bounding Box Crash in Toy Store

## User Feedback / Problem Description

When launching the game with `make up`, Bevy panicked with:
```
assertion failed: min.x <= max.x && min.y <= max.y && min.z <= max.z
at bevy_math/src/bounding/bounded3d/mod.rs:79:9
```
This caused `make: *** [up] Error 101` and dropped the command queue.

## Root Cause Analysis

1. In `src/world/toy_store.rs`, the cashier desk furniture geometry called:
   ```rust
   desk.beam(
       Vec3::new(75.0, 1.2, -200.0),
       Vec3::new(75.0, 1.2, -200.0),
       260.0,
       2.4,
       COUNTER_WOOD,
   );
   ```
   Both endpoints `a` and `b` were identical (`b - a == Vec3::ZERO`).
2. In `src/world/quads.rs`:
   ```rust
   let along = (b - a).normalize_or_zero();
   let side = if along.y.abs() > 0.99 {
       Vec3::X
   } else {
       along.cross(Vec3::Y).normalize()
   };
   ```
   When `along == Vec3::ZERO`, `along.cross(Vec3::Y)` is `Vec3::ZERO`, and calling `.normalize()` produced `NaN`.
   The `NaN` coordinates entered the mesh vertices, which poisoned Bevy's AABB bounding volume computation, failing the assertion `min <= max`.
3. Additionally, spawning empty meshes in Bevy can also cause degenerate AABBs.

## Solution

1. **Defensive Engine Protection (`src/world/quads.rs`):**
   - Guarded `MeshBuilder::beam` against zero-length segments:
     ```rust
     let delta = b - a;
     if delta.length_squared() < 1e-6 {
         return;
     }
     ```
   - Added unit test `degenerate_beams_are_safely_ignored`.
2. **Correct Desk Geometry (`src/world/toy_store.rs`):**
   - Fixed the desk beam endpoints from `(-200.0, -200.0)` to spanning `(-450.0, 50.0)`.
3. **Guard Empty Mesh Spawns (`src/world/toy_store.rs`):**
   - Added `!mesh.is_empty()` checks before spawning procedural entities across room enclosure, counter, block canyon, Hot Wheels, and Scalextric sectors.
