# 2026-11-04 — A new website, and the game updating itself

## User request

- An option to update the game from within the game, from the binaries on
  motorust.germade.dev (the mechanism is the engine's; see its
  `RECORD/2026-11-04.game-updater.WIP.md`).
- A completely new website, with screenshots of the game, in place of the
  current one, which the user found rather plain.

## Implementation

### Updates

- `assets/game.ron`: `updates`, where the game's releases are:
  - `latest`: the site's `version.txt`;
  - `archive`: `motorust-{version}-{target}` under the site's `/downloads/`;
  - `sums`: the GitHub release's `SHA256SUMS.txt`.
- `web/build.sh` writes `version.txt` (the version the site publishes).
- `docs/building.md` ("Updating from the game") says how it works.

### The website (`web/index.html`)

- **Layout:**
  - a top navigation;
  - a full-screen hero on a shot of Costa del Sol, with the logo, the "JUGAR"
    button and its progress bar, the version and a link to the downloads;
  - a row of numbers (9 tracks, 8 bikes, 5 modes, 2 players);
  - a gallery of the nine tracks, each with a screenshot, its length and a
    line about it, Costa del Sol first and wide, marked new, and the shots
    opening big in a dialog;
  - the game's features and modes;
  - the downloads and the quick installer, as before;
  - a footer.
- **Kept as they were**, for `web/build.sh`'s `sed` and the loader: the
  `#game` canvas under the page, `#loader` over it (which now scrolls and is
  the whole page), `#start-btn`, `#progress`, `#status`, the version element
  and the `WASM_BYTES`, `WASM_SHA256` and `GAME_VERSION` lines. The loading
  script and the download links' code are copied unchanged. While the game
  loads, only the hero shows.
- **Trademarks:** the tracks' lines name none of the games, films or
  franchises the tracks are inspired by (the game's own descriptions do).
- **The screenshots** (`web/images/track-*.jpg`, 1280 × 720):
  - taken in the game, under lavapipe, with a temporary harness that hides
    the interface and races from a chosen distance on each track;
  - Costa del Sol's in its new look;
  - about 1.1 MB in all;
  - the old `turbo-bay.jpg` and `welcome.jpg`, which nothing uses any more,
    are removed.

## Verification

- With Playwright, at 1440 × 900 and 390 × 844, the page's width is the

  until `overflow: hidden`.
- `tools/with_engine.sh same cargo test` (the engine at `743fedd`, with the
  updater and `game.ron`'s `updates` read by it): 234 passed, 0 failed,
  1 ignored.

# 2026-11-04 — The binaries' sums on the game's site

## User request

The site and the binaries belong to the game (the engine is shown only as a
library), and the binaries' checksums are better on the site, beside them,
than on GitHub.

## Implementation

- `.github/workflows/release.yml`, the `pages` job: a step sums the
  binaries (`motorust-<version>-SHA256SUMS.txt`) and the R2 upload puts it in
  `downloads/` beside them, before the site, and with it `version.txt`, is
  deployed. When the game sees a new version, its sums are there. The GitHub
  release keeps its own `SHA256SUMS.txt`.
- `assets/game.ron`: `updates.sums` is
  `https://motorust.germade.dev/downloads/motorust-{version}-SHA256SUMS.txt`,
  so everything the game updates from is on its site.
- `web/setup.sh`: `verify_checksum` reads the sums from the site, and from
  the GitHub release only when the site has none (the releases published
  before this change).
- `functions/downloads/[file].js`: a `.txt` is served as `text/plain`.
- `docs/building.md`: the updates' `sums`, and the installer's check.

## Verification

- `bash -n web/setup.sh`: clean; `release.yml` parses as YAML.
- `tools/with_engine.sh same cargo test`: 234 passed, 0 failed, 1 ignored.
- Not run in a release yet: the next one will be the first with the sums on
  the site.
