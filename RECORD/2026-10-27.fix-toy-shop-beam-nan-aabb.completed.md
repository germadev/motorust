# 2026-10-27 — Fix `Aabb3d::from_min_max` Panic on Degenerate `MeshBuilder::beam` in `Toy Shop`

## User Request
Fix the panic encountered when running the game:
```
thread 'Compute Task Pool (2)' panicked at bevy_math-0.19.1/src/bounding/bounded3d/mod.rs:79:9:
assertion failed: min.x <= max.x && min.y <= max.y && min.z <= max.z
```

## Implementation Details
- **Root Cause:**
  1. `Aabb3d::from_min_max(min, max)` in `bevy_math` is called by `Mesh::take_gpu_data()` when `RenderMesh::take_gpu_data` extracts a mesh with `RenderAssetUsages::RENDER_WORLD` to the GPU in `ExtractSchedule`.
  2. `min.x <= max.x && min.y <= max.y && min.z <= max.z` after a `Vec3::min` / `Vec3::max` fold over `Mesh::ATTRIBUTE_POSITION` can only fail if at least one vertex position contains `NaN`.
  3. In `src/world/toy_shop.rs`, `road_pose(track, along)` snapped `along` to the nearest discrete sample index `track.index_at(...)` (spaced ~3.0 m apart), while `spawn_train_line` stepped by `SLEEPER_STEP = 1.25 m` (and the final fractional steps of `spawn_slide_run`, `spawn_scalextric_sector`, and `spawn_hot_wheels_sector` could also round `a0` and `a1` to the same track index `i0 == i1`).
  4. When two consecutive step positions coincided (`a == b`), `MeshBuilder::beam(a, b, ...)` in `src/world/quads.rs` computed `along = (b - a).normalize_or_zero()` (`Vec3::ZERO`) and then `along.cross(Vec3::Y).normalize()`, which divided zero by zero and produced `Vec3::NAN` for every vertex of that beam.
- **Fixes:**
  - **`src/world/quads.rs` (`MeshBuilder::beam`):** Replaced `(b - a).normalize_or_zero()` with `let Some(along) = (b - a).try_normalize() else { return; };` so degenerate zero-length beams are safely skipped without generating `NaN` vertices. Added unit test `degenerate_beam_does_not_produce_nan_vertices`.
  - **`src/world/toy_shop.rs`:**
    - Updated `road_pose(track, along)` to linearly interpolate between consecutive track samples (`i0` and `i0 + 1`) so railway rails (`SLEEPER_STEP = 1.25 m`) and animated toy trains (`roll_toy_trains`) move smoothly and never collapse adjacent steps onto the same point.
    - Guarded `spawn_red_carpet`, `spawn_scalextric_sector`, `spawn_hot_wheels_sector`, and `spawn_slide_run` with `if i0 == i1 { continue; }`, and updated `spawn_red_carpet`'s finish-straight range from `(4180.0, lap)` to `((lap - 110.0).max(105.0), lap)`.
    - Extended `toy_shop_meshes_have_valid_geometry` and `world::tests::a_circuit_is_shown_before_its_rest_comes_and_raced_on_whole` to call `mesh.take_gpu_data()` on all generated meshes so `Aabb3d::from_min_max` is verified in unit tests.
