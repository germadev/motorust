# 2026-11-03 — `make up ENGINE=same`: the engine on the game's branch

## User request

A helper `make up ENGINE=same`, so that the game uses the engine's branch of the
same name as its own.

## Implementation

- `tools/with_engine.sh`: `same` is replaced by the game's current branch
  (`git rev-parse --abbrev-ref HEAD`) before anything else. After that it runs
  as for any branch: checked out in `.tmp/engine/<branch>`, fetched afresh, and
  given to cargo through a `[patch]` with `--config`, with `Cargo.lock` put back
  afterwards.
- It stops with a clear message, instead of falling through to checking out a
  tag or commit of that name:
  - when the game is on no branch (a detached HEAD);
  - when the engine has no branch of that name (`git ls-remote --heads`).
- It works with every target that takes `ENGINE` (`up`, `build`, `app`, `test`,
  `bench`).
- The header of `tools/with_engine.sh`, the Makefile's comment and `up`'s help,
  `docs/building.md` ("The engine") and `docs/architecture.md`'s list of tools
  say so.

## Verification

- `bash -n tools/with_engine.sh`: clean.
- On `ccr-5ceb056d-y3evh6`, which both repositories have:
  `tools/with_engine.sh same cargo tree -p motorust-engine --depth 0` gives
  `motorust-engine v0.0.19 (.../.tmp/engine/ccr-5ceb056d-y3evh6)`, and
  `Cargo.lock` is back as it was.
- On a branch the engine does not have: "ENGINE=same: the engine has no branch
  …", exit 1.
- On a detached HEAD: "ENGINE=same: the game's checkout is on no branch …",
  exit 1.
- `make -n up ENGINE=same` passes `same` on to the script.
- No Rust changed, so `cargo test` was not run again for this.
