# Bike Starting on Its Own with the DualSense

- **Date:** 2026-10-12
- **Topic:** The player's bike accelerated by itself when the race appeared, only with the DualSense connected.
- **Branch:** `claude/awesome-hamilton-hyvwrg`

## User Request

> "Está ocurriendo que al comenzar a jugar, la moto acelera sola"

Follow-up answers: it happens playing with the DualSense, the bike starts without touching anything, it does not happen with the DualSense switched off, and it does not happen with the GuliKit.

## Investigation

- Ran the real game under Xvfb (software Vulkan) with a temporary, uncommitted harness and no input devices: the player's bike stayed at exactly 0 m/s and the same position for 10 s on the grid, with the race not started. Physics (including the new contact code) does not move a parked bike.
- So something read from the DualSense counts as throttle. Throttle on a gamepad is RT/R2 **or Cross/A (South)**, and Cross/A is also the button that confirms in the menus: the press that confirms the bike and enters the race can still be held on the first frames of the race, which counts as throttle, sets `Race::started` and launches the bike. A trigger that does not read zero at rest (e.g. while its adaptive effect is engaged, which only the DualSense has and which is switched on precisely when the race appears) would do the same.
- Could not reproduce on hardware here (no DualSense in the container).

## Implementation Details

- `src/bike/mod.rs`: new `PadArming` (a `Local` of `read_player_input`). A gamepad's throttle and brake count only once that control has been seen at rest (< 0.1) since the race was set up; when a new race is set up or the race is restarted (`Race::started` goes back to false), every control must be released again. Applied to single player and split screen (`read_controller_binding`). Keyboard is unaffected; once a control has been released it passes through untouched, so driving is unchanged.
- Diagnostic log: when the throttle starts the race, `info!` says what pressed it (keyboard, or the controller's name with its RT and A readings), so if it ever happens again the terminal says which input it was.
- `read_player_input` was at Bevy's system-parameter limit: the per-player steering `Local`s are now pairs.
