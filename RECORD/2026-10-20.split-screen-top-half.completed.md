# Two players: the top half of the screen drawn again

**Date:** 2026-10-20. **Branch:** `claude/sleepy-galileo-s35zhl`.

## 1. The second player's camera no longer clears the first's half

### 1.1 User Request
- "In 2P mode the top screen is not seen."

### 1.2 Implementation Details
- Reproduced with a temporary probe (not committed) starting a two-player race under Xvfb: with multisampling (Options > Graphics > Antialiasing "MSAA 4×", the default) both halves showed; with FXAA or no smoothing, the top half was only the colour of the sky (the clear colour), the HUD over it. The second player's camera (`CameraPlayer(1)`, order 1, the bottom half) cleared the picture as it began to draw, and a clear takes the whole picture, not only a camera's viewport: with one sample a pixel the first camera's half, drawn already on the same picture, was wiped.
- `camera::setup_split_cameras`: the second camera made with `ClearColorConfig::None`, so it draws over the picture the first left (its own half drawn over whole, the sky first). Multisampled, Bevy copies the picture into its samples before it draws (its MSAA writeback), so it is right whatever the antialiasing, on every GPU, not only where multisampling happened to keep it.
- Docs: `docs/architecture.md` (`camera.rs`).

### 1.3 Verification & Testing
- New test `the_second_player_s_camera_draws_over_the_first_s_without_clearing_it` (the first camera clears, the second, after it, does not; only one is made).
- `cargo test --release`: 610 passed, 0 failed, 2 ignored. `cargo fmt --check`: clean. `cargo clippy --release --all-targets -- -D warnings`: clean.
- Screenshots (the temporary probe under Xvfb, not committed), a two-player race on Bahía's grid: before, with FXAA and with no smoothing, the top half only sky, with MSAA both halves; after, both halves with each of the three.
