### 1.2 Implementation Details
- **`src/content.rs`** (new): the content pack, the asset source `content://` (`content://music/bahia.mp3` is `assets/music/bahia.mp3`; `content::path`), registered by `ContentPlugin`, added in `main` before `DefaultPlugins` (Bevy builds the sources as its `AssetPlugin` is added):
  - **a desktop development build** (`cargo run`, `cargo test`; `debug_assertions`, not wasm) reads `assets/` from the disk (`FileAssetReader`, by `CARGO_MANIFEST_DIR`, as `data::load` reads the circuits), and builds none of the pack in;
  - **a release build and every web build** serve from memory (`MemoryAssetReader` over a `Dir` of `Value::Static` bytes) the files `assets/pack.txt` lists, built in by `build.rs`.
- **`assets/pack.txt`** (new): the pack's files, one path in `assets/` a line, `#` comments: the eight tracks' songs, the three chill ones and the menus'. The five spare songs in `assets/music/` stay out, as they were (a list rather than every file of a folder, so that nothing unused is built in).
- **`build.rs`**: `pack()` writes `pack.rs` in `OUT_DIR`, `FILES: &[(&str, &[u8])]`, each listed file by its path with `include_bytes!` of its absolute path; it stops the build naming a listed file that is not there. (It already reruns when `assets/` changes.)
- **`Song`** names its file (`file: "music/bahia.mp3"`) instead of holding its bytes; `data::song` makes it from the circuit's file's `file: "bahia.mp3"`, refusing a name that is not an MP3 in `assets/music/` (a path, another extension). `music` in `src/circuits/mod.rs`, the songs built in by name, is gone; `CHILL` and `MENU` name their files.
- **`src/sound/music.rs`**: `SongSource` holds its MP3 as `Arc<[u8]>` (the looped decoder over a `Cursor` of it), loaded by `SongLoader` (an `AssetLoader` for `.mp3`, registered by the `SoundPlugin`; Bevy's own audio reads no MP3 here). `play_music` asks the asset server for the song as it starts (`assets.load(content::path(file))`): it fades in meanwhile, and the song is let go, and unloaded, once it has faded out, so only the songs playing are in memory (each copied out of the binary while it plays).
- **`data::load`**: in a release build it no longer leaves an unused `folder` and an `unwrap_or` on `None` (`cargo clippy --release` failed on them; it was not run before).
- The lobby's test app, which adds the `SoundPlugin`, adds the `ContentPlugin` before its `AssetPlugin`.
- **Docs:** `docs/architecture.md` (`src/content.rs`, `assets/pack.txt`, the music, the circuits, the design decisions, the tests), `docs/tracks.md` (a song by its file; adding a track lists its song in `pack.txt`), `docs/building.md` (what a release build has built in and a development build reads from the disk), `ROADMAP.md` (step 3: the music done).
- Not yet: reloading a file of the pack when it changes on the disk (Bevy's `file_watcher` feature, a watcher for the source); it matters for the circuits and the editor, not for the music.
