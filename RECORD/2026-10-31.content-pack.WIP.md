# The Content Pack (2026-10-31)

Step 3 of "The engine apart from the game" (`ROADMAP.md`; the whole plan in `RECORD/2026-10-31.engine-split-plan.WIP.md`): the game's files loaded through Bevy's asset server, from a content pack, instead of built into the code with `include_bytes!`. The music first, the smallest part.

## 1. The Music

### 1.1 User Request
> "Sigue con 2026-10-31.engine-split-plan.WIP.md" (go on with the engine split plan): steps 1 and 2 done, on with step 3, in the plan's suggested order, the music first.

### 1.2 Implementation Details
- **`src/content.rs`** (new): the content pack, the asset source `content://` (`content://music/bahia.mp3` is `assets/music/bahia.mp3`; `content::path`), registered by `ContentPlugin`, added in `main` before `DefaultPlugins` (Bevy builds the sources as its `AssetPlugin` is added):
  - **a desktop development build** (`cargo run`, `cargo test`; `debug_assertions`, not wasm) reads `assets/` from the disk (`FileAssetReader`, by `CARGO_MANIFEST_DIR`, as `data::load` reads the circuits), and builds none of the pack in;
  - **a release build and every web build** serve from memory (`MemoryAssetReader` over a `Dir` of `Value::Static` bytes) the files `assets/pack.txt` lists, built in by `build.rs`.
- **`assets/pack.txt`** (new): the pack's files, one path in `assets/` a line, `#` comments: the eight tracks' songs, the three chill ones and the menus'. The five spare songs in `assets/music/` stay out, as they were (a list rather than every file of a folder, so that nothing unused is built in).
- **`build.rs`**: `pack()` writes `pack.rs` in `OUT_DIR`, `FILES: &[(&str, &[u8])]`, each listed file by its path with `include_bytes!` of its absolute path; it stops the build naming a listed file that is not there. (It already reruns when `assets/` changes.)
- **`Song`** names its file (`file: "music/bahia.mp3"`) instead of holding its bytes; `data::song` makes it from the circuit's file's `file: "bahia.mp3"`, refusing a name that is not an MP3 in `assets/music/` (a path, another extension). `music` in `src/circuits/mod.rs`, the songs built in by name, is gone; `CHILL` and `MENU` name their files.
- **`src/sound/music.rs`**: `SongSource` holds its MP3 as `Arc<[u8]>` (the looped decoder over a `Cursor` of it), loaded by `SongLoader` (an `AssetLoader` for `.mp3`, registered by the `SoundPlugin`; Bevy's own audio reads no MP3 here). `play_music` asks the asset server for the song as it starts (`assets.load(content::path(file))`): it fades in meanwhile, and the song is let go, and unloaded, once it has faded out, so only the songs playing are in memory (each copied out of the binary while it plays).
- **`data::load`**: in a release build it no longer leaves an unused `folder` and an `unwrap_or` on `None` (`cargo clippy --release` failed on them; it was not run before).
- The lobby's test app, which adds the `SoundPlugin`, adds the `ContentPlugin` before its `AssetPlugin`.
- **Docs:** `docs/architecture.md` (`src/content.rs`, `assets/pack.txt`, the music, the circuits, the design decisions, the tests), `docs/tracks.md` (a song by its file; adding a track lists its song in `pack.txt`), `docs/building.md` (what a release build has built in and a development build reads from the disk), `ROADMAP.md` (step 3: the music done).
- Not yet: reloading a file of the pack when it changes on the disk (Bevy's `file_watcher` feature, a watcher for the source); it matters for the circuits and the editor, not for the music.

### 1.3 Verification & Testing
- New tests: `the_pack_lists_files_that_are_there_once_each`, `a_file_of_the_pack_is_known_by_its_source`, `a_song_loads_from_the_disk_and_from_memory_alike` (a song loaded through an asset server from the disk source and from a memory source as a release build's, the same bytes as the file), `every_song_is_in_the_pack` (each track's, chill and menu song listed in `pack.txt`); `mistakes_are_told` tries a song named `../bahia.mp3`. The music's tests (every song decodes, lasts as it says and loops, its loudness, under the engine) read the MP3s from the disk.
- `cargo test`: 728 passed, 2 ignored. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo clippy --release -- -D warnings` (which compiles the built-in pack, `pack.rs`) clean.
- The game itself (a window, sound) was not run in this container (no display, no audio device); the music's app test plays the menus', the track's and the chill songs' through the asset server's handles.

## 2. Every File in the Pack (2026-11-01)

### 2.1 User Request
> "Adelante con el paso 3" (go ahead with step 3).

### 2.2 Implementation Details
- **Every file the game uses in the pack, none in the code**: the 66 `include_bytes!` and `include_str!` of `assets/` in `src/` are gone. What the game needs as it starts (the world is built at `Startup` from the circuit, the textures and models made into meshes and images there) is read at once, by its path in `assets/`:
  - **`content::file(path) -> &'static [u8]`** and **`content::text(path) -> &'static str`** (`src/content.rs`): in a desktop development build each file is read from the disk the first time it is asked for and kept (leaked, in a map behind a mutex, so asking again costs nothing: the tests ask often); in a release build and on the web it is looked up among the files built in (`built_in::FILES`, in a map made once). Either way a file `assets/pack.txt` leaves out stops the game, saying so: the development build checks the list too (`content::listed`, read from the disk once), so a file missing from it fails at once in `cargo run` and `cargo test`, not only in a release.
  - The music keeps the asset server's way (`content://`), loaded in the background as it plays.
- **The circuits' order as data**: `assets/circuits/circuits.ron` (new) lists the circuits' files in the menu's order; `FILES`, the eight files built in by name in `src/circuits/mod.rs`, is gone (`files()` reads the list and each file from the pack). `data::load`, which chose between the disk and the text built in, is gone with it: `content` makes that choice for every file now. The roster reads `bikes/roster.ron` from the pack (`ROSTER_FILE`).
- **The Meshy bikes** (`src/bike/model/imported.rs`): `Model` names its folder in `assets/models/` instead of holding its six files' bytes; `bike()`, `base_color()`, `metallic_roughness()`, `normal()`, `pilot()` and `pilot_color()` read them from the pack.
- **The rest by path**: the trees', feudal Japan's, Middle-earth's and the toy store's model packs and atlases (`trees.rs`, `japan.rs`, `middle_earth.rs`, `toys.rs`), the textures (`textures.rs`) and the sky's maps (`sky.rs`), the UI font (`vector_art::FONT_FILE`, also for the HUD and the gamepads' art), the start menu's helmet, the gamepads' SVGs and the window's icon.
- **`assets/pack.txt`**: now the whole pack, grouped and commented: the songs, the circuits and their list, the roster, the eight bikes' six files each, the scenery's models, the textures, the UI. Left out, as before: the spare songs, `MotoRUST.jpeg` and `.svg`, the `.icns` and `.ico` (the macOS bundle's and the Windows executable's icons, which `build.rs` and `tools/make-app.sh` take from the disk), `Info.plist`, the credits and the font's licence.
- A release build and the web are as before: the same bytes built into the executable, now listed by `pack.txt` instead of named in the code. A desktop development build builds none of them in (about 120 MB less to link).
- **Docs:** `docs/architecture.md` (`src/content.rs`, `src/circuits/`, `assets/`, the design decisions), `docs/tracks.md` (adding a track: its file in `circuits.ron` and `pack.txt`), `docs/building.md`, `docs/models.md`, `ROADMAP.md` (step 3: every file done; what is left).
- **Left for step 3**: reloading a file when it changes on the disk (for the circuits and the editor); the circuits as assets of their own, loaded in the background, which asks for a loading screen before the world is built. And the code still names the files it reads (the bikes' folders, the model packs' and textures' paths): for step 4 those names become registrations or data.

### 2.3 Verification & Testing
- New tests in `src/content.rs`: `a_file_is_read_once_and_kept` (the same bytes as on the disk, the same slice when asked again; a text file), `a_file_the_pack_leaves_out_is_refused_as_a_release_would` (a spare song, on the disk but not listed). `every_circuit_file_reads` and `mistakes_are_told` read the circuits by their list.
- `cargo test`: 730 passed, 2 ignored. **`cargo test --release`: 730 passed, 2 ignored**: with `debug_assertions` off the tests read every file from the pack built into the test binary, as a release game does (the circuits, the roster, the bikes, the scenery's models and textures, the font, the art), and the unlisted song is refused there too.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo clippy --release -- -D warnings` clean.
- The game itself (a window) was not run in this container (no display); the tests build the world, the bikes, the riders, the textures, the sky and the menus' art from the pack.
