# 2026-10-27 — Game Modes Card Colours & macOS Exit Log Filter

## User Request
1. Explain/address the two shutdown log lines observed when closing the game on macOS:
   - `WARN bevy_ecs::world::command_queue: CommandQueue has un-applied commands being dropped. Did you forget to call SystemState::apply?`
   - `ERROR winit::platform_impl::macos::event_handler: tried to run event handler, but no handler was set`
2. In the game modes menu (`src/modes.rs`), change the colours of `Arcade` and `Carrera` (`Mode::Race`):
   - `Mode::Arcade` switches to the Blue previously used by `Mode::Race` (`Color::srgb(0.04, 0.4, 1.0)`).
   - `Mode::Race` ("Carrera") gets a new colour that harmonises with the rest of the mode cards (`Elimination` red, `Checkpoint` purple, `Free` green, and `Arcade` blue).

## Implementation Details
- **`src/modes.rs`:**
  - Updated `lit(mode: Mode)` so `Mode::Arcade` uses `Color::srgb(0.04, 0.4, 1.0)` (matching the start menu's 1P card `PRIMARY_BLUE`) and `Mode::Race` uses a warm amber-gold `Color::srgb(0.88, 0.46, 0.08)` that shares the tonal depth (`0.88` peak, `0.08` floor, ~3.1:1 contrast ratio with white lettering) of `Mode::Elimination` (`0.88, 0.16, 0.16`), `Mode::Checkpoint` (`0.5, 0.19, 0.88`), and `Mode::Free` (`0.08, 0.66, 0.34`).
  - Updated the unit test in `src/modes.rs` to verify that all five mode cards have distinct colours and readable contrast with white lettering.
- **`src/main.rs`:**
  - Investigated both shutdown messages:
    1. `bevy_ecs::world::command_queue`: Bevy's `ExtractPlugin` disables `auto_insert_apply_deferred` and `apply_final_deferred` on `ExtractSchedule` (applying extracted commands later in the `Render` schedule), and `bevy_winit` queues deferred window-teardown commands on exit; when `WinitAppRunnerState::exiting` runs `world.clear_all()`, any un-applied deferred command buffer from the final frame triggers `CommandQueue::drop`'s warning.
    2. `winit::platform_impl::macos::event_handler`: On `AppExit`, `bevy_winit::system::despawn_windows` moves the `winit::window::Window` into a system-local `Local<Vec<WindowWrapper<Window>>>` (and `ExtractedWindows` in `RenderApp` holds a `RawHandleWrapper` reference) that drops during `World` teardown after `event_loop.run_app` has finished and cleared `winit`'s active `EventHandler`; macOS AppKit synchronously invokes window delegate callbacks (`windowDidResignKey:` / `windowWillClose:`) on `NSWindow` destruction, causing `winit` to log `tried to run event handler, but no handler was set`.
  - Configured `bevy::log::LogPlugin` in `DefaultPlugins` in `src/main.rs` to filter out `bevy_ecs::world::command_queue=error` and `winit::platform_impl::macos::event_handler=off` alongside `bevy::log::DEFAULT_FILTER`.
- **`docs/gameplay.md`:**
  - Updated the description of the Game Mode screen colours (Arcade blue, Race amber).
