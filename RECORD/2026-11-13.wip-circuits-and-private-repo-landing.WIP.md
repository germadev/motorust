# 2026-11-13 · WIP circuits and a landing without the repository's links

## User request

The repository is going private: take its references off the landing page.
Juguetería (the toy store) and Puerto Neón (the hover bikes) are still in
development: say so in the game and on the landing page.

## Implementation

- `web/index.html` (the landing):
  - The footer's "Código en GitHub" link is gone.
  - The desktop downloads always point at the site's own `./downloads/…`
    (the Cloudflare function serves them from R2); served from localhost they
    no longer point at the GitHub release (`isLocal` removed).
  - Juguetería's card has an amber "En desarrollo · WIP" badge (`.badge.wip`)
    and a note under its text.
  - Puerto Neón had no card: it has one now, with the same badge and note,
    8,06 km. There is no screenshot of it in `web/images/` yet, so its picture
    is a neon title over a gradient (`.shot.neon`), to be replaced by a
    capture (`images/track-puerto-neon.jpg`) when there is one.
  - The counts follow the ten circuits: meta descriptions, tagline, the
    numbers row, the section's title, the arcade mode and the lead.
- In the game, `assets/circuits/toy_store.ron` and `puerto_neon.ron` start
  their descriptions (shown on the track select screen) with
  "En desarrollo (WIP) · " / "Work in progress (WIP) · ". The names are left
  as they are: the saved records are keyed by them, and the tests find
  Juguetería by its name.
- `docs/tracks.md`: the table marks both as WIP, with a sentence below it.

Left as they were: `web/setup.sh` falls back to the GitHub release for its
checksums, and `functions/downloads/[file].js` redirects to the GitHub release
when a file is missing from R2. Neither shows on the page, but both stop
working once the repository is private.

## Verification

  notes and Puerto Neón's card lay out like the others.
- `cargo test`: 255 passed, 0 failed, 1 ignored (the circuits, with their new descriptions, read and checked).
