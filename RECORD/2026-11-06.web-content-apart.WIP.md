# 2026-11-06 — The web version: the content apart from the .wasm

## User request

The game on the web took very long to load, or did not load at all and
froze the tab.

## Diagnosis

The published `motorust_bg.wasm` (v0.0.18) was **200.9 MB**: about 62 MB of
code and every file of the content packs (models, textures, circuits, fonts
and the eighteen songs, ~130 MB) built in with `include_bytes!`. The browser
had to download it whole, hold it more than once in memory (the download's
chunks, the joined buffer, the Cache Storage copy, the compiled module) and
start the game with a linear memory holding all of it.

## Implementation

Needs the engine's change of the same date
(`motorust-engine/RECORD/2026-11-06.web-content-apart.WIP.md`), released in
a new tag, and Cargo.toml then moved to it.

- `build.rs`: on `wasm32`, the game's pack is not built in.
- `web/build.sh`: runs the engine's `tools/web_pack.py` (found with
  `tools/engine_dir.sh`), which writes `content.pack` (the game's pack over
  the engine's, minus the songs) and the songs loose in `content/music/`;
  fills `CONTENT_BYTES` and `CONTENT_SHA256` into the page.
- `web/index.html`: downloads the `.wasm` and `content.pack` at once with one
  progress bar, each into a single buffer of its known size (no list of
  chunks joined afterwards); keeps both in Cache Storage (by their SHA-256,
  the old builds' copies dropped, the old 200 MB `.wasm` among them); leaves
  `content.pack` in `globalThis.motorustContent` for the game to take before
  it starts.
- `functions/content.pack.js` and `release.yml`: `content.pack` (52 MB) is
  over the 25 MiB a Pages file may have, so it goes to R2 like the `.wasm`
  and a function serves it, kept for a year (each build asks with `?v=`).
- `docs/building.md` and `docs/architecture.md` updated.

## Verification

- Web build with the engine's branch under a local `[patch]`:
  `motorust_bg.wasm` 68.8 MB (62.4 MB code, 5.8 MB data), `content.pack`
  52.3 MB (97 files), `content/` 72.1 MB (18 songs). First visit downloads
  ~118 MB instead of ~201 MB; the songs only as they play.
- Headless Chromium (SwiftShader): the page downloads both, the game takes
  the pack (the global is gone afterwards), reaches `data-motorust="ready"`
  and shows the menu; the menu's song is fetched from
  `content/music/menu_asphalt_shift.mp3` when it starts.
- `cargo fmt --all --check` passes.

## Still to look at

The code alone is 62 MB. A size-tuned profile for the web (`opt-level = "s"`
or `"z"`, fat LTO, `wasm-opt`) would shrink it a lot, at some cost in speed
to measure first.

## 2026-11-06 — The engine's v0.0.21

The engine's change was released as v0.0.21 (its tag includes
`tools/web_pack.py` and `content::PAGE_GLOBAL`); `Cargo.toml` (both
`[dependencies]` and `[dev-dependencies]`) and `Cargo.lock` moved to it.
