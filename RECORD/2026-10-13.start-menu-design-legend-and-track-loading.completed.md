# Start Menu From Its Design, One Legend Everywhere, Volume Balance, Audit and Track Loading

**Date:** 2026-10-13
**Branch:** `claude/loving-maxwell-vr7uub` (follows commit `344a628`)

## 1. User Request

1. Fix the start menu: it must look like the attached SVG design (`menu-motorust.svg`), and be exactly as wide as the game's title.
2. The controls legend: no background, the same style on every screen, and coherent content. Later: the arrows are not needed in the legend.
3. Volume: FX at 20 % and music at 90 % sounded balanced; those levels must become the new 80 %.
4. The Options menu sits too high.
5. Audit the last commit (`344a628`).
6. Find out why the track selection menu is slow to load.
7. During the work: the highlighted buttons' animated background from the SVG (each button flows its own way) must be there and checked; use the SVG (or equivalent curves) directly instead of raster images; the exit confirmation must show "Exit game" in red when chosen.

## 2. Implementation Details

### 2.1 Start menu (`src/welcome.rs`, `src/menu_card.wgsl`, `src/vector_art.rs`, `assets/ui/helmet.svg`)
- Geometry taken from the SVG (1417 design units wide): 1P card 683 × 342, 2P card 684 × 342 with a 50-unit gap, Options and Exit banners 1417 × 146, row gaps 40 and 36, corner radius 18. Helmet boxes and lettering centres/heights were measured from the SVG in Chromium (`getBoundingClientRect`).
- The whole menu is scaled so its width equals the title's: `MenuWidth` starts from the font's advance of "MOTORUST" at 110 px (swash shaping) and `fit_menu_to_title` (PostUpdate, after layout) sets it to the laid-out width of the title node; the screen is rebuilt if it differs.
- Buttons are `MaterialNode<CardMaterial>` (a `UiMaterial`, shader embedded with `embedded_asset!`): signed-distance rounded corners, the fill colour, and the SVG's chequered flag (90-unit squares, skewX −16°, black 5.5 % / white 3 %) sliding one period (180 units) every 3 s using `globals.time`: 1P → right, 2P → left, Options → up, Exit → down, the vertical flows following the slant (±51.615, ∓180) so the loop is seamless. Colours are mixed in sRGB like the browser, then converted to linear.
- Idle buttons are black at 87 % in linear blending, which looks like the design's 60 % sRGB blend (1 − 0.4^2.2). Highlight colours #0a64ff, #14b24b, #fbbf00, #ff2020; transitions take 0.15 s (`light_cards`, materials kept in `MenuCards` so they never flash on rebuild).
- Vector art at screen resolution (`src/vector_art.rs`): Bevy has no SVG support, but zeno (already in the tree through swash) reads SVG path data. The helmet's curves are kept verbatim in `assets/ui/helmet.svg` and rasterised (even-odd fill) at the exact physical pixel size they take on screen; the old `assets/ui/helmet.png` is gone. The lettering uses the UI font (Russo One) slanted 14°, emboldened 4 % and tracked 7 % without kerning, cropped to the ink and drawn at the exact cap height; it matched the SVG lettering within ~3 % of aspect in a side-by-side comparison, and it works in both languages.
- Navigation remembers the last card of the top row (`navigate`, unit-tested). The dead breathing animation (it queried `Transform`, which UI nodes do not use since Bevy 0.17) and the four procedural chequer textures were removed.
- The welcome screen is rebuilt only when what it shows changes (page, language, device, width, scale factor), not on every selection change.

### 2.2 Controls legend (`src/legend.rs`)
- One look everywhere: no panel, badges styled by device (light keycaps; white PlayStation badges with the symbols in their classic colours; dark Xbox badges with coloured letters; dark Switch badges), white action text with a shadow, centred at the bottom.
- The UI font has no arrows, ticks nor PlayStation symbols: the old legend showed gaps for ↑ ↓ ← → ✕ ○. Those are now drawn as SDF icons (`draw_glyph`, mipmapped) and the remaining ✓/arrow characters in strings were replaced. A test scans every non-comment line of `src/` and fails on any character missing from the UI font.
- Menus use semantic hints (`Keys::Confirm`, `Back`, `Tabs`) with the same words on every screen; directional hints were dropped at the user's request. The race legend is built from the player's actual bindings (keys or buttons of the device in use), hides while paused, and the old test that only checked a copy of the help text inside the test module was replaced by tests of the real code.
- Track select, bike select and the lobby now use the same legend instead of their own hint lines.

### 2.3 Volume (`src/sound/mod.rs`, `src/sound/music.rs`, `src/settings.rs`)
- `fx_gain(level) = level / 80 × 0.2` and `music_gain(level) = level / 80 × 0.9`: 80 % now plays exactly as the old 20 % / 90 %. Settings fields are saved as `fx_level` / `music_level`, so levels saved with the old scale start again at 80 % instead of becoming much quieter. The mixer now starts at the chosen FX level (it used to start at full volume when FX was 0).

### 2.4 Options position (`src/options.rs`)
- The panel has a fixed height and is centred above the legend, so it is lower on every window size while the tabs stay put across sections. Rows were tightened so the Control section's note fits. The modal is rebuilt only when its content changes (it used to rebuild on every mouse move, since `Window` changes with the cursor).

### 2.5 Audit of `344a628` — findings fixed
- Closing Options with Esc/B or "Back" also acted on the screen below in the same frame (welcome → quit confirmation; pause → resume), and opening could act on Options in the same frame, depending on system order. Options input now runs in `OptionsInput`, the welcome and pause menus run after it and ignore the frame Options close in. Covered by `the_key_that_closes_the_options_does_not_resume_the_race` (fails without the guard).
- Cancelling "Exit game" in the pause menu selected "Options" (`3.min(items.len() - 1)` used the confirmation page's length); it now returns to "Exit game".
- The selected-card pulse never ran (UI nodes have no `Transform`).
- Legend glyphs missing from the font (see 2.2); race legend ignored rebinding; the race legend stayed visible under the pause menu.
- `update_input_device` marked `ActiveController` as changed on every key or button press, rebuilding menus continuously; it now writes only on change.
- The "Controllers updated" message never disappeared (nothing rebuilt the modal when it expired).
- Key and button names in the Control table were Spanish in the English UI; they are localised now.
- An unrelated AI test threshold had been relaxed (`falls <= 2` → `<= 4`); it passes with the original value, which is restored.
- `image` had been made a dependency of every target only for the helmet PNG; it is native-only again.
- Obsolete hint strings were removed, and `docs/gameplay.md` / `docs/architecture.md` now describe the current menus, legend, Options and loading.

### 2.6 Track selection loading (`src/world/mod.rs`, `src/world/terrain.rs`)
- Cause: entering Tracks built every other circuit synchronously in one frame (`cache_all_circuits`). Measured in the dev profile: Bay 0.6 s, Turbo Bay 2.2 s, Loop Island 1.2 s, so the screen froze ~3.4 s before appearing (more on first entry, and again after every return).
- Fix: the pure part (track, `Terrain::new`, `Terrain::meshes`, track edges — about 80 % of the time) is computed on `AsyncComputeTaskPool`; finished circuits are spawned hidden, one per frame. A circuit chosen before it is ready is waited for (native) or computed on the spot (web, where tasks share the main thread). The sea mesh, identical for every circuit, is now built once and shared.
