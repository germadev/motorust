# DualSense Accelerating by Itself Again; Pause "Exit game" in Red

**Date:** 2026-10-13
**Branch:** `claude/loving-maxwell-vr7uub`

## 1. User Request
- "Vuelve a ocurrir que con el dualsense acelera solo" (with the DualSense, the bike accelerates by itself again).
- "La opción de salir del juego del menú de pausa, también con el fondo rojo" (the pause menu's "Exit game" option, red when chosen too, like its confirmation).

## 2. Investigation
- No change to the gamepad throttle path (`read_player_input`, `PadArming`, `squeezed`, `TRIGGER_REST`) since the previous fix (`af74ad2`), so the earlier causes (the Cross press that enters the race, a trigger resting slightly pressed) are still covered.
- `src/gamepads/apple.rs`: on every bike or wall hit, both DualSense triggers switch to `TriggerEffect::Vibration`, applied with `setModeVibrationWithAmplitudes_frequency` and the same amplitude (0.40–0.75) in all ten zones of the travel, `start_position` ignored. Vibrating from position 0, the trigger arm shakes at rest and its own sensor reads it as pressed: throttle (and brake) the player never asked for.
- `CollisionImpact::record` keeps the impact timer up while the bike keeps touching another bike or a wall, so the vibration goes on while leaning, the phantom throttle pushes the bike on, and the contact goes on: a loop. No DualSense here to confirm on hardware.

## 3. Implementation Details
- `src/gamepads.rs`: `vibration_zones(start, amplitude)` builds the ten positional amplitudes with nothing before `start`; `VIBRATION_START = 0.3`, checked at compile time to stay well past `TRIGGER_REST` (0.15, now `pub` in `src/bike/mod.rs`).
- `src/gamepads/apple.rs`: the vibration effect uses `vibration_zones(start_position, …)`, and collisions vibrate from `VIBRATION_START`: the vibration is felt while the trigger is pressed, and a trigger at rest stays still.
- `src/pause.rs`: "Exit game" in the pause menu is a `Row::danger` too, red with white text when chosen.

## 4. Verification & Testing
- New test `gamepads::tests::a_vibrating_trigger_is_still_until_pressed`; `apple::tests::collision_impact_triggers_soft_vibration` now also checks the start position (macOS only).
- `cargo test`: 247 passed. `cargo fmt --check` clean, `cargo clippy --all-targets` no warnings.
- `src/gamepads/apple.rs` only builds on macOS; a cross-check for `aarch64-apple-darwin` cannot run here (C dependencies need the macOS SDK), so the change was reviewed by hand against `objc2-game-controller` 0.3.2 (`values: [c_float; 10]`).
